# 07｜整合驗收、乾淨安裝與可玩發行包

前置：完成 [01–06](00_MASTER_PLAN.zh-TW.md#2-文件順序與完成關係) 的必要 gate。終點是玩家可直接操作的 MVP，不是提交下一份計畫。

**本階段終點：**同一個 release commit 的程式、正式美術、來源資料設定與存檔版本，通過自動回歸及實際 UI 遊玩，產生可核對的 Windows x64 發行包。此文件的測試數字都是要求後續執行的門檻，不是本次已取得的結果。

## Phase 07.1｜凍結驗收範圍與證據格式

### 實作

確認本次內容清單符合 00：一個有實際服務的聚落、來源室內、至少六種來源 RDB 模板與約 8–12 實例的生成地牢、三種角色、至少八種敵人、近戰／弓箭／魔法、完整主要任務與短支線、裝備特效、正式素材、勝敗與存讀檔。

鎖定本次 source profile、rulesVersion、generatorVersion、artCatalogVersion、saveSchemaVersion 和候選程式 commit。測試後修改公式、素材 mapping 或地圖規則，受影響測試必須重跑，不可以舊報告包裝新 build。

建立 `release-readiness.json` 與人可讀摘要，每個檢查記錄實際命令、環境、輸入 seed、預期、結果、log／截圖位置及對應 commit。狀態只用 PASS、FAIL、BLOCKED、SKIPPED；後兩者不等於成功。產生一份效果 closure 分母及垂直排除清單的快照，防止後續為了數字好看而縮小分母。

不要要求全世界、原版全部主線、公會、外部 mod 或舊 DFU 存檔相容才發布；也不能反過來刪掉已承諾的非垂直物品特效、正式美術或存檔，把它們當未來版本。

### Gate

每個最終需求都有可執行的驗證方法，且至少能分清來源對照、內部一致性、agent 視覺檢查、實際 UI 遊玩四種不同證據。沒有獨立來源真值的地方不得標成原作逐項等價。

## Phase 07.2｜自動回歸與壓力測試

### 必要測試矩陣

| 面向 | 驗證內容 | 最低門檻 |
|---|---|---|
| 資料／索引 | item group、groupIndex、templateIndex、來源 ID、裝備槽、法術／附魔參照 | 正式包所有使用資料可解析；未知欄位與排除理由可查。 |
| 公式 | 百分骰、3–97 邊界、傷害端點／取整、部位、材質、怪物特殊規則 | 固定輸入與骰序列的 golden tests 通過；不能只比較平均值。 |
| 回合／RNG | UI 不耗時、速度、麻痺、DoT、反射鏈、死亡不再行動、動畫無副作用 | 重播同序列 hash 一致，預覽／取消不改 RNG。 |
| 地圖 | 模板與實例隔離、門／室內配對、多層接縫、斜角、任務依賴 | 來源樣本與合成難例全通過；無錯層捷徑與必要路線死鎖。 |
| 生成器 | 端口、起終點、鑰匙／開關、返回路徑、有限失敗處理 | 至少 1,000 固定 seed；所有輸出或合法備援均通過；真正生成成功率至少 95%。 |
| 敵人／戰鬥 | 八類敵人能力、範圍、射箭、施法、材質限制、多段攻擊 | 至少 100 組固定戰鬥案例，沒有穿牆、重複反擊或重複扣資源。 |
| 道具／特效 | 05 的完整來源依賴閉包、各神器、參數域及觸發／解除 | 非垂直 closure 的實作與驗證覆蓋率 100%；排除表另列，不算已實作。 |
| 存讀檔 | RNG、已生成地圖、附魔、中毒、召喚、Recall、已領獎、損壞檔 | 各檢查點重載後與不中斷重播一致；不複製物品、不重置地圖。 |
| 美術 | 真實檔案、mapping、crop、alpha、拼接、pivot、正式圖塊 | 無缺失 assetId；關鍵內容有實際 agent 視覺語意檢查。 |

1,000 seed 是本次回歸樣本，不是宣稱已證明所有隨機布局永遠正確。備援不得是繞開原來源模板的空房間，亦不得用總是備援來通過生成器測試。

效果參數化 handler 可共用測試，但每個來源效果／神器都必須有可追蹤的適用測試；名稱存在、registry 裡有 entry、沒有 exception 或只測五個起始道具都不能算 100%。未知的非垂直效果使本 gate FAIL／BLOCKED，不准變更 exporter 把它藏起來。

### 執行環境與命令

使用 01 的 `rg` wrapper，記錄其實際展開的 Unity 命令及 exit code。範例職責為 `rg test core`、`rg test integration`、`rg test effects`、`rg test world-seeds`、`rg validate-art`；命令尚未存在時在此補齊，而不是在報告貼上不可執行的示例。

EditMode 的純資料／規則測試可以走無圖形模式；實際渲染、美術截圖及需要圖形裝置的 PlayMode 測試不能一律加 `-nographics`。Unity Test Framework 的完成／退出流程依既有版本操作，不能因過早退出得到空測試 XML 後仍視為成功。[E2][E3，見 00]

CI 分無原版資源的合成／核心測試，以及有合法本機資源的整合測試。原版資源與生圖憑證不提交 repo，也不寫進公開 log。缺少合法資源、Unity 啟用或 build module 時明確 BLOCKED，不能以所有整合測試 SKIPPED 宣告通過。

### Gate

測試報告可由其他 agent 依 seed／profile 重跑。失敗案例保存為小型可重現 regression，不靠一次性人工改圖消除。生圖輸出規整可以 deterministic 重跑，生成模型本身不承諾能再次產生相同原圖。

## Phase 07.3｜真正操作發行畫面完成冒險

### 必做遊玩驗收

在非 Editor 的候選包中，三種 preset 各完成至少一輪主要任務與勝利；另做一次正常死亡／重開或載入。至少一輪使用正常 UI 完成買賣、補箭、施法、換裝、使用附魔物、休息、存檔、完全關閉程式、重新載入與交付。

可由 agent 的桌面操作能力執行並保存操作軌跡；有 headless simulation bot 仍不能省略 UI 測試。不存在桌面操作能力時，不可假稱看到勝利畫面；保留此項 BLOCKED 與實際可驗證範圍。

覆蓋八方向射擊、斜角牆、門、可取消的瞄準、魔力與箭量耗盡、背包滿、低耐久破損、中毒後換圖、Recall、效果到期與任務物返回。確認訊息真實說明原因，不把「材質無效」顯示成普通閃躲。

使用 EffectsLab 實際操作至少一件有非單純傷害功能的神器、一個反射／吸收效果、一個地形能力，以及一個有負面條件的附魔。正常冒險與 Lab 都走同一組 domain handlers，禁止 Lab 另寫特效假的展示路徑。

### 視覺與操作

檢查 1280×720 與 960×540 的原尺寸畫面：繁體中文、狀態、箭量、門、敵人與物品可辨識；沒有缺字方框、裁切按鈕、atlas 邊緣滲色、生成格線／文字、不可見的關鍵目標或被 UI 擋住的地圖。

調整視窗、音量、UI scale，切回遊戲後不多走一步、不誤發箭。長按鍵有明確的輸入重複節奏，不能因掉幀累積數十個未預期的攻擊。關閉選單後不要把關閉鍵同時送成遊戲動作。

記錄實測一輪時長、常見死亡原因、玩家準備是否足以處理主線材質／法術需求。20–40 分鐘只是目標；優先修卡關、資訊不明與不合理重複路程，不為了時長調整而無聲更改原公式。

### Gate

有帶版本／seed 的實際標題、聚落、探索、戰鬥、背包、存讀檔及勝败畫面證據。單張美術樣張、Editor Scene 視窗或純 simulation 成功訊息均不符合本 gate。

## Phase 07.4｜效能、資源與乾淨安裝

### 實作

在記錄 CPU、RAM、GPU、解析度與 OS 的測試機實測啟動、第一次來源準備、後續載入、切圖／切場景、存讀檔、指令延遲与長時間遊玩記憶體。不能只寫「應該很快」。可把正常格子動作提交的第 95 百分位目標設為 100 ms 內，視覺平移／動畫目標 60 FPS；這是測試機上的目標，不是所有硬體保證。

做至少 20 次聚落／地牢往返與 30 分鐘實際遊玩，觀察是否重複註冊效果事件、累積未銷毀圖像、RNG／狀態漂移或場景快取無限制成長。異常 log、memory drift 與最慢指令有紀錄。效能修正不得改掉戰鬥結果或來源 semantics。

從乾淨目錄解壓到含空白／中文的路徑，以一般使用者執行；第一次選合法原版資料路徑，完成初始化後關閉網路再玩一輪。source resources 仍需依分發方案存在，不代表能刪掉所需來源檔；錯誤訊息要明確指出缺少哪類資源。

可先編譯 MVP 使用的模板並快取，不要求首次啟動轉完世界。正式路徑中禁止再呼叫 image generation、LLM 或 agent。發行檔不可內含 API key、使用者帳密、機器專屬絕對路徑，亦不可把開發者的測試存檔當新玩家起始狀態。

DFU 程式碼授權與原遊戲資產來源分別記錄；不能因 fork 程式碼有 MIT 標示，就將原資產或任意第三方素材視為同一授權。本機原版資源的取得／讀取遵循原有安裝方式，未確認可再散布的來源包不隨 MVP 重分發。生成素材保留實際工具及使用條件紀錄，不主張沒有查證的權利保證。

### Gate

乾淨安裝後能完成來源設定並正常進入遊戲；執行時離線可用，不要求安裝 Unity Editor 或 agent harness。首次資料準備與快取狀態可理解。效能結果和測試硬體已寫入報告。

## Phase 07.5｜打包、交付與 goal 完成判定

### 發行包最少內容

```text
RoguelikeMVP/                 Windows x64 可執行檔及所需 runtime 資料
README.zh-TW.md               安裝、原版資料準備、啟動、控制、存檔位置
CHANGELOG.md                 本版本真正完成的內容
KNOWN_ISSUES.md              已知但不阻礙核心流程的問題
BUILD_INFO.json             程式 commit、source/rules/art/save profile 與建置環境
TEST_REPORT.md              可核查的測試摘要與證據位置
ASSET_PROVENANCE.md          正式素材產生／衍生與來源記錄
```

上述是後續 agent 要產出的發行結構，不是目前 repo 中的既有檔案。產生 ZIP 與 SHA-256；記錄實際包的位置及摘要。GitHub Release 或 Actions artifact 可在具備可用發布工具時提供，但建立標籤或一個連結不等於二進位檔真的上傳成功。發布前確認可實際取得該檔。

程式、採用的正式生成圖集／衍生素材、prompt、工具腳本与小型測試資料可以版本化；大體積失敗圖集、原 ARENA2、憑證與暫存快取不要混入。針對必要合法資產保留清楚的安裝來源說明，而非交付無法啟動的空殼。

最後逐項對照 00–06。只有在正常冒險、正式美術、非垂直物品特效、勝敗、存檔與乾淨發行包都通過時，才將 `PROGRESS.md` 的 goal 標為完成。仍有非垂直效果 pending、核心 UI 無法使用、假資料、缺正式圖像、未實際測過包或資料缺失，都不能只列入 KNOWN_ISSUES 然後宣布 MVP 完成。

### 交付訊息

向使用者提供實際 commit／發行包位置、如何啟動、原版資源要求、最短一輪玩法、測試環境与已知限制。明確区分「已玩過與通過」及「未驗證」，不虛構測試人數、成功率、圖像生成或全世界相容。

若某項真正被工具或環境阻擋，可交付已完成的可核查內容，但狀態是部分完成／BLOCKED，不改定義把它叫做完整 MVP。正常必要環境齊備時，agent 應持續修復到本階段通過，不例行停在每個 phase 徵詢下一步。

## 完成檢核

- [ ] 01：真來源與獨立 2D 執行入口；可重現核心。
- [ ] 02：來源 block、原配置回歸、新種子布局与合法接縫。
- [ ] 03：真實生圖、可重跑切圖、正式美術、可用介面与音效。
- [ ] 04：同一回合規則下的碰撞近戰、弓箭、五種法術目標与敵人。
- [ ] 05：原物品特效閉包完整、非垂直 pending 為零、實際功能与測試。
- [ ] 06：接任務到勝敗、商店／休息／成長、無重複領獎、可靠存讀檔。
- [ ] 07：實際非 Editor 遊玩、乾淨離線安裝、可取得且經驗證的 Windows 發行包。

本清單在計畫提交時全部未勾選。只有後續實作取得證據才更新；本次文件提交本身不通過上述任一遊戲完成 gate。

# 03｜生圖美術工廠與正式探索介面

前置：[01 資料契約](01_FOUNDATION_AND_DATA.zh-TW.md)、[02 可行走地圖](02_BLOCK_WORLD.zh-TW.md)。下一階段：[04 戰鬥](04_TURN_COMBAT.zh-TW.md)。

**本階段終點：**玩家以正式像素素材探索地圖，而非看除錯色塊。素材由執行開發的 agent harness 生圖工具產生，腳本完成切割、規整、導入及映射；遊戲執行時不生圖。

## Phase 03.1｜固定美術方向與素材 ID

### 已決定的風格

採紅白機啟發的俯視中古奇幻像素風，不要求真實 NES 的硬體限制。世界圖塊及一般角色以 **32×32 邏輯像素**為標準；大型敵人可用 64×64 圖像，但 gameplay footprint 由資料定義，不能跟著透明區大小變動。統一俯視角度、輪廓、光源方向與像素密度；不用透視地板、3D 寫實陰影或生圖文字。

使用從首份合格風格樣張抽取並保存的共用調色盤，目標不超過 32 種基礎色；透明不計。原始生成大圖可保留較多顏色，正式輸出以 deterministic quantization 規整。這是美術風格目標，不是原作配色重現。

地圖可於 1280×720 遊玩，最小 960×540；以整數倍率呈現像素、不開 mipmap、不讓雙線性濾波模糊圖塊。文字使用獨立字型渲染及可調 UI scale，不把繁體中文擠成 32 像素圖塊上的生圖字。

### 素材目錄

先建立 `art-spec.json`，包含 stable assetId、語意、使用情境、sheet/row/column、pivot、尺寸、透明政策和 fallbackId。預設六張 4×4 圖集，每張 16 格，共 96 個母素材位置；這是產製預算，不代表必須每種裝備各生一格。

| 圖集 | 主要內容 |
|---|---|
| S00 Terrain | 石地兩種、泥地、草地、道路、淺／深水、石／木牆、上／下階梯、陷阱等。 |
| S01 Props | 開／關門、鎖門、開／關寶箱、桶、桌、床、祭壇、商店／旅店標誌、開關、傳送點等。 |
| S02 Actors | 三個角色 preset、任務／商店／旅店 NPC、八種主要敵人，餘格留變體。 |
| S03 Equipment | 刀劍、鈍器、斧、短／長弓、箭、盾、各類護甲、戒指／護符等類型母圖。 |
| S04 Items | 回復／法力／狀態藥水、卷軸、書、材料、金幣、鑰匙、任務物、神器語意母圖等。 |
| S05 Effects | 斬擊、物理命中、未命中、火／冰／毒／電／魔法、治療、護盾、隱形、召喚／傳送等。 |

若 source catalog 需要的獨特形態不在表內，先判斷是否可用類型母圖＋材質／符號 overlay。只對真正無法辨識的類別增補小圖集，不能因上百個數值變體就生上百張圖。

### Gate

每個本次可見內容 ID 都有 asset mapping 計畫。角色、敵人、門、可拾物及地面危害在小尺寸下可區分；不能只靠顏色表示敵我或狀態。透明／tileable／pivot 規則清楚。

## Phase 03.2｜透過 harness 真實生圖

### 實作

使用 01 已驗證存在的 image-generation tool。記錄實際工具、模型可得的版本資訊、完整 prompt、可用參數、引用樣張、輸出檔與 hash。不假設所有工具有 seed、透明背景或固定尺寸能力；能力不同由薄 adapter 處理，不另寫模型服務。

物件圖集的基準要求：1024×1024、4 列×4 欄、每格 256×256、物件中心對齊、至少 32 像素安全邊界、無文字／格號／邊框／格線。每格只畫指定物件，底色統一且不得是物件內主要顏色；工具支援真透明時优先使用。**不要把棋盤格圖案當成真的 alpha。**

terrain 圖集另用滿格、可鋪貼的提示，不沿用物件圖集的透明留白條件。固定 row-major 資產顺序在 prompt 和 `art-spec.json` 同時列明。

可重用的物件 prompt 模板：

```text
產生一張俯視中古奇幻遊戲素材圖集。畫布 1024×1024，
精確 4×4 等分，每格 256×256。依下方逐列清單放置物件。
所有物件採相同角度、光源、輪廓及像素密度，風格遵循參考樣張。
每格只有一件物件，完整置中且四周保留至少 32 像素空間。
不得出現文字、數字、格線、畫框、寫實質感或越過格界的陰影。
背景：[工具支援的透明背景，否則指定一致純色]。
第一列：[asset 0 的語意]；[asset 1]；[asset 2]；[asset 3]。
第二至四列：依 manifest 展開。
```

這是給後續 agent 的提示模板，不是聲稱已執行生圖。先產生一份涵蓋角色、敵人、門與地面的風格樣張，由 agent 用視覺能力檢查，再把合格結果作後續參考。正常情況不需要人工逐張批准。

### 重試規則

同張圖集最多三次整體嘗試；局部錯誤不要反覆重生全部素材，改成 2×2 或單格補圖，寫回相同 assetId。重試不能無限制產生成本。工具缺失／額度不足是真 blocker；可繼續其他程式 phase，但正式美術 gate 不准用假圖片生成紀錄通過。

### Gate

每份採用圖集都存在可讀影像檔、prompt 與 provenance。不得只提交 prompt 或遠端暫時 URL；不得用網路搜尋素材冒充本次生成。

## Phase 03.3｜腳本切圖、像素規整與 atlas

### 實作順序

1. 驗證實際尺寸與色彩格式。尺寸不符但比例正確時先規整到標準尺寸；比例不符則退回生成，不用非等比例拉伸修好。
2. 依 manifest 的整數格位切割，不用 OCR 辨識格號，也不靠模型逐次猜物件框。當生成物件跨格或整張分隔不齊時，該格失敗，不能切到鄰格後仍算成功。
3. 物件圖使用真 alpha 或從邊界 flood-fill 去除指定底色；保持內部同色區域，避免把白眼睛、武器高光或衣服切穿。不要只留最大 connected component，弓弦、法杖或粒子可能本來分離。
4. 在安全邊界內縮放到 32×32，保留一致的腳底／中心 pivot；做 palette quantization、nearest-neighbor 輸出及必要的 alpha 閾值處理。所有步驟參數保存。
5. 地板／水面檢查四邊平鋪；需要时用確定性 wrap blending 生成衍生素材，或重生該格。拼接測試不能只看原大圖。
6. 產生 runtime atlas 與 assetId→sprite metadata，加入 padding／extrusion，導入 Unity 設定為 Point filtering、無 mipmap、適當壓縮／不壓縮，測試不漏出鄰格邊緣。

座標明訂：manifest row 從圖像頂端數；Unity sprite rect 若採底端原點，使用 `y = imageHeight - (row + 1) * cellHeight`，不能同時在前處理與 importer 各翻轉一次。

### 自動檢查

圖檔可解碼、格數、輸出尺寸、assetId 唯一、邊界截斷、非空比例、alpha 邊缘、調色盤及缺失 mapping 都能腳本測。另輸出 contact sheet 與放大／原尺寸預覽，由 agent 視覺檢查格位語意、人物肢體／武器辨識、門開關差別、風格一致性。

**幾何檢查通過不代表語意正確。**不能把「有非透明像素」當成弓或藥水已正確產出。無法可靠自動檢出的美術問題，保留實際 agent 視覺檢查紀錄；不宣稱完全無誤。

### Gate

切圖可離線重跑且產生同 hash；生成模型不需再次呼叫。所有正式 assetId 有實際 sprite，關鍵格不跨邊、無格線／文字污染，材質與尺寸一致。UI、地圖在最小支援解析度可讀。

## Phase 03.4｜高度重用與正式 renderer

### 實作

裝備按類型母圖重用，材質以固定 palette swap 表示；附魔、毒、耐久低等以小 overlay 表示。名稱、數值及狀態由 UI 真實文字補充。不要為每個相同護甲的材質另做獨立生圖。

角色可以一張静態基礎 sprite 加朝向標记、輕微位移与命中閃爍完成 MVP；需要兩幀循環時可從母圖生成可重現衍生幀。不得要求八方向全套攻擊动画後才接戰鬥。高辨識怪物／神器可補專用圖，不把全部特殊物件畫成同一袋錢。

世界渲染分離 terrain、牆／門、道具、角色、特效、迷霧。所有互動物件獨立，不烘焙在靜態背景。播放 GameEvents，但 renderer 不變更戰鬥／inventory 狀態。換 skin 不影響碰撞或存檔 ID。

音效可沿用合法本機原版資源的既有讀取，或用腳本產生短促復古音效；兩者保留來源說明。移動、命中、未命中、施法、拾取、受傷、勝敗至少有可關閉的基本音效；不以配樂製作阻塞 MVP。

### Gate

同一物品的世界圖示、背包圖示與描述一致。開門、死亡、拾取與狀態特效在一個已提交動作後只播放一次。離線完全可渲染，不向模型發請求。

## Phase 03.5｜FOV、迷霧與探索 UI

### 實作

FOV 使用地圖的遮擋資料；保存 neverSeen、remembered、visible 三態。探索半徑預設 8 格，光源和黑暗修正可由 05 接入。門打開即重算，樓層／場景變更重算；從未探索的房間不因小地圖或 tooltip 洩漏敵人。

UI 包含血量、魔力、耐力、負重、武器／箭量、回合／世界時間、狀態圖示、訊息 log、可查看的操作表、背包／裝備入口和目前目標欄。訊息使用可保留歷史的繁體中文，不只用瞬間飄字。

瞄準 UI 在 04 接命中邏輯前就使用同一份 `PreviewTrajectory` 契約。不得重寫一個只是好看的瞄準線算法。只預覽目前可知的遮擋，不讓預覽暴露戰霧內隱藏敵人。

滑鼠可選物件／UI，键盘可完成主要操作。MVP 不要求全地圖滑鼠自動尋路；避免自動跑步讓角色連續送出攻擊或錯過危險。

### 本階段交接

提交正式採用 atlas、切割工具、`art-spec`、provenance、mapping、渲染設定與視覺 QA。原始生成大圖放明確的源素材目錄；大量失敗版本不用全部塞進 Unity import。正常發行畫面不得使用除錯字母／方塊作为最終美術。

此階段的視覺目標、圖集規格與生成策略為本計畫設計。既有 Unity Tilemap／UI 套件依据見 [00 的 S5](00_MASTER_PLAN.zh-TW.md#10-源碼與外部依據)。

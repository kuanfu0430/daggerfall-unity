# 02｜區塊世界、2D 通行與種子布局

前置：[01](01_FOUNDATION_AND_DATA.zh-TW.md)。下一階段：[03](03_ART_AND_EXPLORATION.zh-TW.md)。本次產品邊界以 [00](00_MASTER_PLAN.zh-TW.md) 為準。

**本階段終點：**玩家可走過村莊、建築室內與真正由來源 block 構成的地牢；原配置與新種子配置共用同一組裝器。可以暫用除錯圖塊，不能把手寫矩形測試房間充當最終來源地圖。

## Phase 02.1｜固定座標、模板格式與 MVP 池

### 實作

沿用 `MapsFile`、RMB／RDB 載入、建築資料綁定和室內子紀錄。原版通常按 `MAPS.BSA` 的固定配置組裝，不是每次進門重抽；SmallerDungeons 只作重組接點參照。[S9][S11][S12]

建立不可變 `BlockTemplate` 和獨立 `BlockInstanceState`。最少保存：來源識別、局部格網、surface／顯示層、靜態遮擋、門與機關、ports、入口及任務 anchors、source-to-cell 對照。來源高度可留在編譯資料，正常 gameplay 只在各 surface 的 2D 格上運行。

世界固定使用 x/z 平面；圖像 row 的上下反轉只做一次。RDB 與 RMB 邊長不同，不可共用一個數字。先以 32 DF units 作水平採樣候選，遇窄門丟失則整個 MVP profile 改為 16 並重編譯；本 goal 不做多解析度混合框架。最終值在 profile 記錄，不可每張圖私自變動。

用資料與測試選至少六種來源 RDB 模板，包含起點候選、一般內部、需要的邊界，以及帶門／容器／任務 marker 的樣本。模板候選若強制要求自由跳躍、攀牆或尚未支援機關則不進本次池；仍留在 catalog，標示「MVP map pool 外」，不是從來源消失。

選一個來源聚落與其真實室內，優先含或能透過已保留建築資料提供商店及旅店服務的地點。服務 UI 可由 06 接上。選擇流程依來源 ID 排序及能力條件完成，不要求使用者逐地點挑選。

### Gate

source ID、座標、門／marker 全可追蹤；同模板至少放兩次並證明狀態隔離。MVP 池的選擇／排除清單已保存；不聲稱全世界覆蓋。

## Phase 02.2｜模板編譯：最短來源路徑

### 實作

RMB 先利用 `CityNavigation` 的 64×64 街道導航底稿和地表 tile；在需要更細解析度、門口與高度資訊時補幾何。這是遊走 NPC 的導航資料，不是完整玩家碰撞，不能將其直接當最終真值。[S10]

RDB 與室內使用既有幾何讀取，加多層高度場／表面抽取。按前次報告重用 Recast／DotRecast；如舊 Unity 套件不相容，Unity 匯出中立資料，再由獨立編譯工具處理。不要為這個 MVP 寫通用 3D 重建引擎。

生成 `walkable`、`blocksSight`、`blocksProjectile`、`terrainType`、`movementCost`、`hazardFlags`，不要用同一個布林值代替所有行為。圖片透明與否不得決定通行。

樓梯與斜坡按已求出的表面連接保留；重疊房間不合併。原幾何無法忠實處理但需要改編的情況，另建 `adapted-2d` 模板並保存來源對照，不覆蓋 `source-layout`。

多 span 中不適合步行的區域可以不在 MVP 活動池；但門、任務物、裝飾与需其他條件開啟的通道不應被當成噪音刪掉。動態門從靜態牆分離，初始關門不等於永久封路。

### Gate

至少通過：兩層交叉通道不誤接、窄门未消失、關門／開門影響通行、上下樓接對 surface、同一模板幾何快取可重用。聯合編譯的兩塊樣本與分塊拼接具有一致邊界連接。

## Phase 02.3｜組裝、轉場與互動

### 實作

`LocationManifest` 保存 mode、seed、revision、template instances、來源 block 順序、入口、ports 配對與地點資料。instanceObjectId 帶 location／instance／局部物件 key；建築的全域識別須帶 mapId，不能只用 buildingKey。

跨 block 依世界位置、端口範圍、實際高度及可通行條件接合，不能直接讓 A 的 layer 0 接 B 的 layer 0。需要鄰居上下文的 erosion／接縫做小範圍重算；複雜特例可用 superblock，不回到全地圖每次重編譯。

門、容器、開關使用來源 action graph 建立映射，提供以下最小互動：普通門開關、鎖門與鑰匙／開鎖接口、容器開啟、開關改變通路、明確樓梯／傳送轉場。尚未實作 action 的模板不能靠可見的開關圖示通過驗收。

入口與出口成對，建築 interior 使用來源 RMB 子紀錄，不依外觀猜房間。轉場保持角色、物品、地圖實例狀態與單一世界時鐘，並為 destination 指定安全入口格。進出不重置已開寶箱或已死亡敵人。

斜向移動政策：兩個相鄰正交格都可通過時才可斜向移動；門框與角落亦套用。移動花費先按 00/04 通用動作規則，地形額外成本為明確整數倍率。

### Gate

村莊 → 室內 → 村莊、村莊 → 地牢 → 村莊可來回操作。原配置樣本可載入。兩份同模板門及容器互不污染；開門未把另一層牆也打開；無效轉場不吞玩家或任務物。

## Phase 02.4｜有限、可重現的新布局生成

### 實作

新增 `SeededLayoutProvider`，只產生和原配置相同的 manifest；不要做另一套 renderer。從已通過的 MVP 模板池選約 8–12 個實例，以端口相容性做小型約束搜尋／回溯。

首版不任意旋轉、鏡像來源模板。日後只有對應變換的門、marker、action 及 ports 全部通過測試，才准加入某種旋轉版本。邊界模板不是萬用蓋子，必須對端口逐一匹配。

每個 seed 使用固定候選排序與獨立 world RNG；最多 64 次布局嘗試。失敗時使用隨 build 提供且通過驗證的來源模板備援布局，保存 `usedFallback` 及理由。不得無限重試、偷偷挖通牆或讓未完成地圖進入遊戲。正式測試至少 95% 種子產生真正的新合法布局，不能總是備援。

布局先決定，再分配任務與掉落。主要目標必須有可達且可返回的有效 anchor；有鑰匙／開關時驗證狀態依賴，不能讓鑰匙生成在自己的鎖後面。非強制支路可有額外危險或道具條件，不要求每個格子永遠可走。

使用階段／區域 tags 管理難度，不以每次載入重抽敵人或地圖達成隨機性。來源主線／固定地點不被生成器覆蓋。將新 manifest 在任務使用前凍結，保存完整結果與 seed，版本升級不自動改舊 run。

### Gate

至少 100 個固定 seed 的回歸：無非法 port、無任務死鎖、可到目標並返回；相同 seed、profile 與版本得到相同 manifest hash；記錄真正生成比例與 fallback。這是回歸證據，不宣稱數學證明所有 seed 都成功。

## Phase 02.5｜為 2D 能力預留可玩地形

### 實作

本 goal 不引入跳躍及攀爬；仍要讓保留的地形能力真正有用途。定義普通地面、淺水、深水危害、地面陷阱、門與安全轉場五類狀態。地形本身遵守固定 cell flags，來源沒有的示範組合可放在明示的 `adapted-2d` 支路／特效驗證場。

深水是同一平面上的可進入危險地形，普通角色會耗氣／受傷；不建立水下第三維。Levitate 的 2D 映射可免疫地面陷阱及深水危害，WaterWalking 對水面免耗氣，WaterBreathing 對耗氣傷害提供免疫；詳細時間与結算由 05 實作。能力到期必須有確定規則，不能把角色刪掉或瞬移到另一層。

本次正常主線不得把這些能力作不可替代的強制通關條件；可在支路或驗證場展示收益。地圖只發出 `EnteredTerrain`／`TerrainExposure` 事件，不在 Tilemap renderer 扣血。

### Gate 與交接

輸出模板庫、兩種 manifest provider、來源／2D 對照、互動物件、地形事件和測試 seed。此時玩家真的能探索完整路線，但戰鬥與冒險目標尚未接上。更新 `PROGRESS.md` 後進 03，不擴張到全世界轉換。
